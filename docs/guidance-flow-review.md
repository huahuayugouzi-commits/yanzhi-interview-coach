# 补充信息后提炼表达引导

## 完成的流程
首次回答 → AI 诊断与一个追问 → 用户补充真实信息 → AI 提炼框架、最多三个关键词和简短提示 → 用户自主完整重说 → 首次回答与最终重说对比。

首次诊断不再展示 retry_hints 或提前生成框架。已有 clear 结果可直接结束；自愿重练时补充可留空，再从已有充分回答提炼组织框架。

## 实现位置
- `src/App.tsx`：复用第三步增加补充与引导子状态，独立显示表达框架、关键词、重说提示和引文依据。补充、完整重说均可录音转录或手输。生成失败保留补充，修改补充清除旧引导与最终回答；编辑首次材料清除旧补充。可选本地草稿保存补充，恢复后重新生成引导。隐私说明补充了引导请求的数据发送范围。
- `server/app.mjs`：新增 `/api/guidance`，与诊断、对比共用口令保护、小时与每日额度、并发限制及请求体限制。
- `server/contracts.mjs`、`schemas/guidance*.schema.json`：独立 framework、keywords、reminder、supporting_quotes 字段。关键词最多三个；引用必须连续出自首次回答或补充，补充非空时必须引用补充。原诊断与对比契约保留兼容。
- `server/prompts.mjs`：首次诊断只诊断和追问；独立引导根据原题、首次回答及补充生成组织槽位，不编造经历或完整范文，不机械 STAR。引用校验不代表能自动发现框架所有事实错误，仍需模型质量验收。
- `server/coach.mjs`：选择独立引导 Schema，格式修复保持在引导任务，不要求诊断字段。
- `scripts/export-schemas.mjs`：同步导出新增契约。

## 对比规则
补充内容用于提炼框架，不会以 second_answer 发送。`/api/compare` 只接收首次回答与最终自主重说，并参考原题和追问。没有将补充或模型提示当成候选人已在最终回答中说过的话。

## 费用与部署
本轮只使用本地 mock 测试，真实模型与 ASR 调用均为零，未部署。未来实际训练会多一次提炼引导请求，计入同一限流额度，格式修复仍最多额外一次。未修改现有模型密钥、型号或供应商。

上线需要前后端一起重新构建部署；不能只更新前端，否则新增 guidance 接口不存在。真实框架质量、事实一致性和不生成范文的遵守情况仍待授权后的真实模型与人工验收，不能把流程测试通过算作模型效果通过。

## 本轮测试结果
44/44 Node 接口、安全、契约测试通过；28/28 桌面与393×852手机流程测试通过；TypeScript、生产构建与diff检查通过。新增覆盖补充后显示引导、三个入口完整闭环、失败重试、修改失效、草稿恢复及clear自愿练习。页面中的模型与ASR成功响应为mock，真实生成质量未验证。
