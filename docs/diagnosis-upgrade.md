# 诊断升级 V1.1（2026-11-17）

## 思路与原因
旧版把测试通过等闭环词设为必须 clear，导致工作清单也可能被过早认可。新版按题目与 JD 识别主要能力，区分表达清楚和能力证据充分；每次聚焦一个可补充缺口，避免靠加长反馈制造价值。

## 修改结果
- 新增 capability_focus、evidence_assessment（完整度与依据）、issue_impact（缺口影响），同步严格 Schema 与页面。
- needs_retry 必须有连续原文依据和缺口影响，服务端拒绝无依据纠偏；clear 必须证据充分并说明依据。
- 工作清单、概括性方案和泛泛满意评价不能因含有测试通过自动 clear。具体内部验证、定性反馈依然是有效证据；不强迫数字、不编造经历。
- 二次对比围绕原追问判断解决程度；解决后不换标准挑新问题。清晰分支保留自愿练习，不强行制造追问。
- 页面将“表达已经清楚”改为“本题关键证据已充分”，增加证据判断与为什么值得补充；顶部版本改为 MVP 1.1。

## 验证
27/27 Node 接口、安全与契约测试；TypeScript 和构建通过；14/14 桌面与手机流程测试（模型、ASR 成功交互使用 mock），新增展示断言另行复测。
真实 DeepSeek 最终一轮：5/5 首答状态符合预期，2/2 对比符合预期。报告：docs/evaluation/evidence-upgrade.json。语义为 Codex 自审，小样本不等于泛化准确率或真实用户价值已验证。
真实试验最初出现新增字段被放错层级而校验拒绝，已增加明确 JSON 层级示例，最终一轮全部通过。仍保留格式失败提示与至多一次修复重试。
