## Prompt 修改
- 先区分“充分说明 / 已提到但未展开 / 未提供”，已有选择必须在 heard 或 evidence_assessment.reason 被承认。
- 缺少理由不等于没有决策；已给具体行动不等于职责清单。归属不清时只澄清该选择的本人参与，不能擅自认定其拍板，也不泛问全项目职责。
- 完整项目介绍看整体能力证据；单点深答围绕原问题。出现技术词不会自动触发技术深挖。
- 已有决策优先锚定原话补一个重要未解点；已充分时 clear。只在确无相关贡献时补案例。
- 修改原“PRD、Prompt、测试清单即需重说”规则，避免忽视清单中夹带的真实范围取舍。
- 继续复用原字段生成简短框架、最多三个关键词与提示，不写完整答案。

## 验收边界
`tests/decision-depth.json` 是六条输入与人工候选；`tests/decision-depth.test.mjs` 检查输入、JSON/引用/单追问兼容、原输入不变和策略文本存在。它们不证明模型会正确选缺口，不等于语义测试通过。

Golden 10 条与其他已有测试继续运行；真实诊断、自然度、优先级及无重复追问效果仍需同输入新旧 Prompt 的真实输出与人工复核。不得依据此文宣称诊断准确率提升。
