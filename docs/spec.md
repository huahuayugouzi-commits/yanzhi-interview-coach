## 一、产品定义

**目标用户**

有工作经验、正在准备面试的求职者。

**核心使用场景**

正式面试前 1–3 天，用户希望通过 5–10 分钟的训练，确认自己是否把真实经历、个人贡献和岗位能力表达清楚。

**核心痛点**

用户知道自己做过什么，但回答容易啰嗦、逻辑混乱、缺少重点，不知道面试官是否听懂，也不知道有没有讲出面试官关心的能力证据。

**产品定位**

AI 模拟目标岗位面试官的信息接收视角，帮助用户清楚表达真实经历和岗位价值。

**差异化**

不是普通模拟面试，不是替用户生成标准答案，而是：

听懂用户 → 找出关键缺口 → 自然追问 → 引导重说 → 对比改善。

## 二、MVP 功能（严格控制范围）

开发一个响应式 Web 应用，优先适配电脑，同时支持手机浏览器。

### 页面 1：训练准备

- 输入目标岗位名称
- 粘贴 JD（必填）
- 粘贴简历（选填）
- 选择训练题目：
  1. 请做一个自我介绍。
  2. 请介绍一个你负责的项目。
- 点击「开始训练」

### 页面 2：首次回答与 AI 诊断

- 浏览器录音，建议 60–120 秒
- 支持停止、重新录制
- 语音转文字
- 支持手动编辑转录内容
- 提交给 AI 诊断

AI 反馈展示三个区域：

**① 我听懂了**

简洁复述用户明确表达的信息。

**② 我还想了解**

指出最影响面试官理解的一个信息缺口。

**③ 我想追问你**

提出一个自然、有针对性的引导问题。

附带最多三个简短重说提示词。

### 页面 3：重新回答与效果对比

- 用户根据引导问题再次录音
- 转录并允许修改
- AI 比较两次回答
- 展示：
  - 哪些信息变清楚了
  - 关键能力证据是否更完整
  - 还有什么需要改善
- 支持重新训练或结束

第二次回答的评价必须同时参考原始面试问题与 AI 引导问题，避免用户只回答追问却被错误判定为偏题。

## 三、AI 核心规则

你是「AI 面试表达教练」。

你模拟目标岗位面试官的信息接收视角，帮助求职者清楚表达真实经历。

你不是招聘决策者，不能预测面试结果。

输入：

- job_description：必填
- resume：选填
- question：必填
- answer：必填

诊断规则：

1. 根据 JD 和面试问题识别关键能力证据要求。
2. 只根据用户实际回答判断已经表达的信息。
3. 识别最重要的信息缺口。
4. 每轮最多指出一个主要问题。
5. 通过一个自然的开放式问题引导用户自己回答。
6. 若回答已清晰，不强行挑错。
7. 若转录内容无法理解，要求重新录音或补充内容。

问题优先级：

1. 没有回答问题
2. 缺少个人贡献或关键能力证据
3. 逻辑混乱
4. 冗余重复

严格禁止：

- 编造用户经历、数字和结果
- 将简历内容冒充为用户已经说出的内容
- 提供完整标准答案
- 输出虚构的面试通过率
- 声称知道真实 HR 的想法
- 一次提出多个无关问题

## 四、AI 反馈输出 Schema

首次诊断使用以下 JSON 结构：

```json
{
  "status": "needs_retry",
  "heard": "我听懂了你参与过大型项目，并负责跨团队协调。",
  "main_issue": "但我还不清楚你个人具体推动了什么工作。",
  "evidence_quote": "负责跨团队协调",
  "guiding_question": "你能举一个自己亲自协调并解决的问题吗？",
  "retry_hints": [
    "个人职责",
    "具体行动",
    "最终结果"
  ]
}
```

status 仅允许：

- needs_retry
- clear
- insufficient

规则：

- clear 时不强行纠偏。
- insufficient 时请求补充或重新录音。
- evidence_quote 必须是原回答中的连续原文，否则为 null。
- main_issue 和 guiding_question 允许为 null。
- retry_hints 最多三个。

请生成正式 JSON Schema，并在服务端进行严格校验。

第二次回答对比请设计独立的最小 JSON Schema，不要复用首次诊断结构导致语义混乱。

## 五、增强 AI 反馈的结构清晰度与活人感

请参考以下开源 Skill：

1. https://github.com/noamseg/interview-coach-skill
2. https://github.com/janestreet/agent_skills
3. https://github.com/4citeB4U/LeeWay-Agent-Skills

要求：

- 先检查实际仓库、SKILL.md 和许可证。
- 只提取适合本产品的结构化反馈、苏格拉底追问和自然对话规则。
- 不要安装整套无关 Skill。
- 如仓库不可访问，直接使用下面的内置规则继续开发，不得阻塞项目。

**内置自然反馈规则**

1. 先回应用户真正说了什么，再指出一个缺口。
2. 每轮只追问一个关键问题。
3. 反馈使用自然、简洁、专业的中文。
4. 不机械地重复「首先、其次、最后」。
5. 不使用过度鼓励或空泛夸奖。
6. 不像老师批改作文，而像有经验的面试官在认真倾听。
7. 根据用户具体回答生成追问，不使用固定模板敷衍。
8. 回答已经清楚时，应认可有效表达，不强行纠偏。

示例：

不推荐：

「你的回答缺少个人贡献，建议使用 STAR 法则优化。」

推荐：

「我大概了解这个项目做了什么，但还没听清楚你个人发挥了什么作用。你刚才提到跨部门协调，能不能挑一件你亲自推动的事情具体讲讲？」

自然感必须建立在事实准确和追问有效的基础上，不能通过增加口头禅来伪装。

## 七、技术方案

优先使用最小技术栈：

- 前端：React + Vite + TypeScript
- 后端：Node.js + Express
- AI：通过服务端调用可配置的 LLM API
- 语音转录：使用可配置的 ASR 服务，优先复用现有可用能力
- 存储：MVP 优先使用浏览器本地存储
- 不引入数据库，除非有明确必要
- 不引入 RAG、多 Agent、复杂工作流框架

要求：

1. API Key 只能存放在服务端环境变量。
2. 不得将 API Key 暴露到浏览器。
3. 提供 `.env.example`。
4. AI 调用失败时有明确提示和重试机制。
5. 语音转录失败时允许用户手动输入回答继续训练。
6. 不提供伪造的 AI 诊断结果。
7. 不把用户的简历和录音写入不必要的日志。
8. 如调用外部模型服务，明确提示数据会发送给该服务。
9. 不要为了支持多模型而引入复杂架构；先实现一种真实可用的服务接口。
