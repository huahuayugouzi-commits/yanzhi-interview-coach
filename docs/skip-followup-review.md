# 追问必要性与跳过重说验收

## 改动范围
- server/prompts.mjs：在既有诊断策略上增加必要性门槛。当前题目必需的能力证据缺口才触发补充；可选的项目/技术深挖不打断自我介绍。结构、简洁度、口语等问题仍走已有建议路径；真实证据不足时仍允许一个开放追问。提示不得预设使用特定工具或技术。
- src/App.tsx：首次追问卡片、补充页增加“跳过，直接重说”。复用原有Guidance空补充路径，无接口或Schema改动；新增本轮跳过状态，支持失败重试、导航往返、稍后补充和Compare。
- tests/skip-followup.test.mjs：3项新增契约/API Mock/规则回归。
- tests/e2e.spec.ts：2项新流程，各覆盖桌面与手机。

## 契约与事实边界
跳过请求使用已有 guiding_question=null、supplement=""，保留首次answer、capability_focus及已有expression_advice。简历/JD仍为背景，不能冒充口头表达。原诊断保留，不改成clear，不声称证据充分。尚未提交的补充草稿保留在页面，但不会发送给该次Guidance。Compare也使用null追问，按原题与既有能力焦点比较两次真实回答，不假装原追问已答。

用户稍后选择修改补充并提交时，恢复原追问和实际补充；若实际修改已有内容，继续使用上一轮确认与下游失效逻辑。
